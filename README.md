# LifePilot

Персональный помощник: жизненный вопрос → дерево решений → действия → обратная связь → прогресс. Интерфейс на русском языке, пять категорий, внутренний календарь и необязательный живой AI.

## Быстрый запуск

Требуется Node.js 22+ и npm.

```bash
npm ci
npm run dev
```

Откройте [localhost:3010](http://localhost:3010) и нажмите **«Попробовать демо»**. Порт 3010 выбран, чтобы не занимать распространённый порт 3000. Для другого порта: `npm run dev -- --port 3011`.

Демо запускается без ключей: пройдите онбординг, откройте «Мои задачи», выберите экзамен или первую стирку, раскройте две ветки, отметьте действия и сохраните результат. Данные демо сохраняются в localStorage этого браузера. После перезагрузки нажмите «Попробовать демо» для возвращения. Это не облачный аккаунт; реальные пароли в демо не вводятся.

Без живого AI доступны все шесть готовых сценариев и наставник с явно обозначенными подготовленными ответами. Произвольные вопросы сохраняются как задачи в ожидании разбора. Индивидуальные деревья и персональные рекомендации **не имитируются** и требуют API. Для живого AI нужен облачный аккаунт: его запросы аутентифицируются и ограничиваются на сервере.

## Облачные данные и авторизация

1. Создайте проект Supabase. Скопируйте `.env.example` в `.env.local` и заполните:

   ```dotenv
   NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-publishable-key
   SUPABASE_SERVICE_ROLE_KEY=your-server-only-service-role-key
   ```

   Все три значения обязательны для облачного режима. `SUPABASE_SERVICE_ROLE_KEY` используется только сервером; не добавляйте к нему префикс `NEXT_PUBLIC_`.

2. Примените `supabase/migrations/202610250001_initial.sql` через Supabase SQL Editor или `supabase db push` в привязанном проекте. Файл создаёт таблицу и политики доступа; не запускайте его повторно поверх существующей таблицы.
3. В Authentication включите провайдер Email и подтверждение почты. Задайте Site URL `http://localhost:3010` и разрешите Redirect URL `http://localhost:3010/auth/confirm` и `http://localhost:3010/auth/confirm?next=/reset-password`. При публикации добавьте точные HTTPS-адреса своего домена.
4. В шаблоне Confirm signup используйте ссылку:

   ```html
   <a href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=signup"
     >Подтвердить почту</a
   >
   ```

   В шаблоне Reset Password:

   ```html
   <a
     href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery&next=/reset-password"
     >Изменить пароль</a
   >
   ```

5. Перезапустите приложение. Зарегистрируйте пользователя, подтвердите почту и пройдите онбординг. Для публичного использования настройте SMTP и ограничения Supabase Auth.

Клиент может читать только свой документ состояния через RLS. Прямые записи от `anon`/`authenticated` запрещены. Server Actions проверяют сессию, валидируют команду, вычисляют изменения и записывают их через серверный ключ. Персональные страницы не кэшируются. Proxy обновляет cookie сессии перед серверным рендерингом.

## Подключение AI

В `.env.local` задайте серверные переменные:

```dotenv
AI_BASE_URL=https://your-provider.example/v1
AI_MODEL=your-model-id
AI_API_KEY=your-api-key
AI_TIMEOUT_MS=30000
```

Провайдер должен поддерживать `POST {AI_BASE_URL}/chat/completions`, массив `messages`, `max_tokens` и ответ `choices[0].message.content` с JSON. Базовый URL включает `/v1`, если этого требует провайдер. Отдельный SDK не нужен. Модель должна уметь возвращать JSON без Markdown; дерево проверяется по схеме, включая отсутствие циклов и недоступных узлов. Некорректные ответы отклоняются, сохранённая задача не теряется. Не все API с похожим интерфейсом полностью совместимы — проверяйте выбранную модель.

В облачном режиме:

- На главной введите проблему. В задаче уточните результат, срок и ограничения, затем постройте дерево.
- В «Идеях» нажмите «Предложить идеи». Принятие рекомендации создаёт задачу; генерация её дерева выполняется после уточнений.
- Откройте наставника в задаче: он получает контекст выбранного пути, выполненных действий, результата и последних сообщений.

Ключ не отправляется в браузер. Сервер ограничивает AI-запросы шестью в минуту на аккаунт и задаёт таймаут. В модель передаётся контекст текущей задачи и целей пользователя, а для рекомендаций — профиль и названия задач. AI не принимает решений о баллах и статусе навыка.

## Поведение приложения

- **Главная:** календарь и поле вопроса. Нажатие даты только раскрывает задачи выбранного дня. Категории имеют одинаковые цвета во всех экранах.
- **Мои задачи:** задачи из поля «Что сейчас занимает твои мысли?», принятых идей и готовых сценариев; поиск, категории и сортировка. Отдельной формы ручного добавления нет.
- **Идеи:** AI-рекомендации и библиотека шести готовых сценариев, доступных без модели. Каждое новое прохождение — отдельная задача.
- **Дерево:** выбранная карточка раскрывает следующий уровень. Предыдущие уровни доступны для смены выбора. Отметки прежних веток сохраняются; процент рассчитывается только по чек-листу текущего пути. После сохранения результата прохождение закрывается для изменений.
- **Прогресс:** 10 баллов за первое выполнение действия, 20 за обратную связь по завершённому пути. Повторные запросы не начисляют баллы. Статус навыка — самоотчёт: попытка → «Осваиваю»; самостоятельный успех → «Делаю самостоятельно»; два самостоятельных успеха в разных прохождениях → «Закреплено».
- **Напоминания:** только внутри открытого приложения, на основе собственных дат пользователя. Инициативные вопросы изначально выключены. Вопросы учитывают согласие, настройки, частоту и часовой пояс. Нет push, фоновой доставки или внешнего календаря. Обработка происходит при открытии облачного аккаунта или действии пользователя. Для демонстрации включите инициативные вопросы и нажмите «Проверить демо-событие» в настройках.
- **Приватность:** очистка истории удаляет диалоги, текст обратной связи и текущие уведомления; задачи и прогресс сохраняются. Удаление аккаунта удаляет связанные данные. В демо соответствующая кнопка очищает только localStorage.

## Устройство

- `src/lib/domain.ts` — типы, валидация команд, правила дерева, прогресса и событий; общий код для сервера и локального демо.
- `src/lib/scenarios.ts` — библиотека сценариев с конкретными действиями и подсказками.
- `src/lib/store.ts` — версия документа и optimistic concurrency: условная запись JSONB по `user_id` и `revision`, повтор после конфликта. Баллы и отметки действия сохраняются одной операцией PostgreSQL.
- `src/app/actions.ts` — проверяемые команды и авторизация; `src/app/api/ai/route.ts` — серверные AI-запросы.
- `src/components/` — экраны и общие элементы; `src/app/globals.css` — визуальная система и адаптивная вёрстка.

Сущности пользователя, задач, дерева, обратной связи, диалогов, рекомендаций, навыков и достижений сохраняются в одном типизированном документе `user_state.state` версии 1. Статус навыка вычисляется по результатам прохождений. Для MVP это позволяет атомарно обновлять несколько связанных сущностей. Изменение формата документа требует явной миграции версии; неизвестная версия не загружается. Лимит — 500 задач на аккаунт; в диалоге хранится до 100 сообщений, в AI-контекст передаются последние 16.

## Проверки

```bash
npm run typecheck
npm run lint
npm run format:check
npm test
npx playwright install chromium
npm run test:e2e
npm run test:db
npm run build
npm start
```

Перед браузерными тестами автоматически выполняется production-сборка. Playwright поднимает отдельный production-сервер на порту **3210**, не переиспользует чужие процессы и проверяет Chromium на desktop и mobile viewport. Скриншоты и trace сохраняются в ignored `test-results/`. `npm run test:db` требует Docker и образ `postgres:17-alpine` (при отсутствии: `docker pull postgres:17-alpine`); запускает временную изолированную БД без публикации портов и постоянных томов и удаляет контейнер после проверки.

Unit-тесты проверяют правила прогресса, смену веток, согласие, ограничения AI, валидацию и ошибки транспорта. Проверка PostgreSQL подтверждает миграцию, RLS, запрет клиентских записей, CAS и каскад удаления. Она использует минимальные тестовые роли Auth и не подменяет проверку настоящего Supabase Auth. Тесты AI используют mock транспорта, а не живую модель.

Перед публичной приёмкой отдельно проверьте реальную регистрацию и письма восстановления, два разных аккаунта, сохранение между устройствами, генерацию деревьев для разных вопросов и ответы наставника выбранной модели.

## Публикация на Vercel

Импортируйте репозиторий как Next.js-проект, задайте Node.js 22 и перечисленные переменные окружения в настройках Vercel. Примените миграцию к рабочему Supabase, обновите Site URL, Redirect URL и почтовые шаблоны на публичный домен. Build command — `npm run build`, зависимости устанавливаются из `package-lock.json`. Vercel управляет запуском самостоятельно; локальный порт 3010 не является настройкой хостинга.

После деплоя пройдите основной сценарий по HTTPS-ссылке без календарных интеграций. Проверяйте Preview и Production раздельно: переменные и разрешённые редиректы могут различаться. Внешние аккаунты, ключи и публичный деплой не создаются автоматически этим репозиторием.
