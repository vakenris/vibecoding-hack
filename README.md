# LifePilot

Персональный помощник: жизненный вопрос → дерево решений → действия → обратная связь → прогресс. Интерфейс на русском языке, пять категорий, внутренний календарь и необязательный живой AI.

## Быстрый запуск

Требуется Node.js 22.21+ и npm.

```bash
npm ci
npm run dev
```

Откройте [localhost:3010](http://localhost:3010) и нажмите **«Попробовать демо»**. Порт 3010 выбран, чтобы не занимать распространённый порт 3000. Для другого порта: `npm run dev -- --port 3011`.

Демо запускается без ключей: пройдите онбординг, откройте «Мои задачи», выберите экзамен или первую стирку, пройдите четыре уровня выбора, отметьте действия или задачу целиком и при желании сохраните результат. Данные демо сохраняются в localStorage этого браузера. После перезагрузки нажмите «Попробовать демо» для возвращения. Это не облачный аккаунт; реальные пароли в демо не вводятся.

### Локальный профиль, документы и CalDAV

Для профиля без регистрации и Supabase:

```bash
LIFEPILOT_MODE=local npm run dev
# После npm run build:
LIFEPILOT_MODE=local npm start
```

Режим можно задать и в `.env.local`. Одна команда запускает Next.js и отдельный обработчик заданий. При заданных `HTTP_PROXY`/`HTTPS_PROXY` запуск учитывает их для AI API, а loopback-адреса исключены из прокси; `NODE_USE_ENV_PROXY=0` явно отключает это поведение. Сервер слушает только `127.0.0.1:3010`; переопределение hostname в локальном режиме запрещено. Другой порт: `npm run dev -- --port 3011`. Закрытие вкладки не останавливает обработку. Пока приложение выключено, обработка не выполняется; после запуска незавершённые задания возобновляются. Блокировка SQLite допускает только одного активного обработчика, задания имеют версии и повторяются после временных сетевых ошибок с ограниченной задержкой. Смена ветки и выполнение отменяют устаревшую работу.

SQLite хранится в `~/.local/share/lifepilot/lifepilot.sqlite`; `LOCAL_DATA_DIR` задаёт другой каталог. Оригиналы документов лежат в его подкаталоге `documents/`, извлечённый текст — в SQLite. Каталог имеет права `0700`, база и локальный ключ календаря — `0600`. Пароль приложения зашифрован AES-256-GCM с отдельным файлом `calendar.key`; для восстановления подключения сохраняйте этот файл вместе с базой. Резервную копию всего каталога делайте при остановленном приложении, чтобы включить согласованную базу и WAL. Данные и секреты не добавляйте в Git. Сохранённое браузерное демо можно однократно перенести в пустой локальный профиль; исходный ключ localStorage не удаляется. Перенесённые задачи не отправляются в календарь автоматически.

В настройках заполните HTTPS URL CalDAV, логин и пароль приложения, нажмите **«Проверить и подключить»**. Выберите один календарь для записи и календари для проверки занятости; первоначально проверяются все доступные. Календарь для записи также всегда проверяется. Поддерживаются Basic authentication и прямые URL CalDAV на том же сервере; межсерверные перенаправления, OAuth и приглашения не поддерживаются. HTTP допускается только для тестового loopback-сервера, явно заданного через `LOCAL_CALDAV_HTTP_URL=http://127.0.0.1:5232`. Пароль не возвращается в браузер и не передаётся AI. Отключение сохраняет созданные события и останавливает синхронизацию.

Новая задача из вопроса, сценария или принятой идеи запускает агента: цель → подробное дерево → предложенный путь с объяснением → длительности → свободное время → отдельный VEVENT каждого шага. Выбор пользователя имеет приоритет. Для старой задачи используйте **«Запланировать шаги»**. Подробное дерево строится по частям: структура, затем группы конечных чек-листов. Черновик сохраняется в SQLite, повтор продолжает незавершённую часть; итог по-прежнему проверяется целиком на глубину и содержание. Работа с моделью требует серверных `AI_*` переменных ниже; без неё задача остаётся сохранённой с явным сообщением. При неоднозначной цели или нехватке времени агент запрашивает уточнение и не создаёт частичное расписание. Настройки по умолчанию: все дни, 09:00–21:00, 14 дней, неизвестная длительность 30 минут, перерыв 10 минут. Звонки и обращения ограничены буднями и дневным окном 09:00–17:00; это окно планирования, фактические часы организации нужно проверить отдельно.

На главной можно прикрепить **один PDF, DOCX или TXT** и необязательное пояснение. Нажатие **«Разобрать»** сохраняет одну основную задачу и запускает обработку. Лимиты: 5 МиБ, 50 страниц PDF, 100 000 извлечённых символов. PDF извлекается через `pdf-parse`, DOCX через Mammoth, TXT читается как строгий UTF-8. Нет OCR, поддержки `.doc` и защищённых паролем PDF. Для потока разбора заданы лимиты V8: 256 МиБ старого поколения, 32 МиБ нового поколения и 30 секунд; распаковка DOCX — 25 МиБ, 2000 записей, не более 10 МиБ на запись. Внешние ссылки не загружаются. Превышения и повреждённые файлы дают явную ошибку без обрезания. Большой текст обрабатывается частями. Требования и сроки показываются с исходными страницами/абзацами и проверяемыми цитатами. Для календарного срока принимается подтверждённая точная дата; неполный/относительный срок нужно уточнить. Команды внутри документа рассматриваются как текст, модель не получает сетевых инструментов или календарных секретов.

В карточке задачи доступны фазы, объяснение выбранного пути, расписание, журнал, повтор и уточнение. Оригинал можно скачать или удалить вместе с извлечённым текстом; задача сохраняется. Внутренний календарь на главной показывает шаги, открывает родительскую задачу и позволяет отметить выполнение. Выполнение шага удаляет его событие, выполнение задачи — события всех её шагов; снятие отметки снова планирует невыполненные действия. При смене ветки удаляются старые незавершённые события. Используются стабильные UID, локальные связи и условные запросы с ETag. Чужие события участвуют только в проверке занятости. Внешний перенос собственного события сохраняется; внешнее удаление не означает выполнения шага и не отменяется автоматическим пересозданием. Для восстановления есть отдельное явное действие. Синхронизация асинхронна: при сетевой ошибке статус задачи сохраняется сразу, а удаление/создание событий повторяется обработчиком. Изменения извне сверяются при новом действии пользователя; постоянного фонового пересмотра календаря нет.

Уточнение цели, доступного времени или срока пересчитывает оценки длительности и времени суток, сохраняя дерево и выбранные ветки. Простой повтор без новых уточнений использует сохранённые оценки. Существующие события автоматически не перемещаются; если они заканчиваются после нового явного или извлечённого срока, план получает статус «Нужно уточнение». Срок проверяется по окончанию события в часовом поясе профиля; завершить событие точно на границе срока допустимо. Перенос отдельного повторения за горизонт не исключает из занятости последующие регулярные встречи.

Этот режим предназначен для локального компьютера. В Vercel остаётся отдельный облачный режим без новых файловых и календарных интеграций.

Без живого AI доступны готовые сценарии и наставник с подготовленными ответами. Индивидуальные деревья и рекомендации требуют API и работают как в локальном профиле, так и в облачном аккаунте.

## Облачные данные и авторизация

1. Создайте проект Supabase. Скопируйте `.env.example` в `.env.local` и заполните:

   ```dotenv
   NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-publishable-key
   SUPABASE_SERVICE_ROLE_KEY=your-server-only-service-role-key
   ```

   Все три значения обязательны для облачного режима. `SUPABASE_SERVICE_ROLE_KEY` используется только сервером; не добавляйте к нему префикс `NEXT_PUBLIC_`.

2. Примените `supabase/migrations/202610250001_initial.sql` через Supabase SQL Editor или `supabase db push` в привязанном проекте. Файл создаёт таблицу и политики доступа; не запускайте его повторно поверх существующей таблицы.
3. В Authentication включите провайдер Email и подтверждение почты. Задайте Site URL `http://localhost:3010` и разрешите Redirect URL `http://localhost:3010/auth/confirm` и `http://localhost:3010/auth/confirm?next=/reset-password`. При публикации добавьте точные HTTPS-адреса своего домена.
4. В шаблоне Confirm signup используйте ссылку:

   ```html
   <a href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=signup"
     >Подтвердить почту</a
   >
   ```

   В шаблоне Reset Password:

   ```html
   <a
     href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery&next=/reset-password"
     >Изменить пароль</a
   >
   ```

5. Перезапустите приложение. Зарегистрируйте пользователя, подтвердите почту и пройдите онбординг. Для публичного использования настройте SMTP и ограничения Supabase Auth.

Клиент может читать только свой документ состояния через RLS. Прямые записи от `anon`/`authenticated` запрещены. Server Actions проверяют сессию, валидируют команду, вычисляют изменения и записывают их через серверный ключ. Персональные страницы не кэшируются. Proxy обновляет cookie сессии перед серверным рендерингом.

## Подключение AI

В `.env.local` задайте серверные переменные:

```dotenv
AI_BASE_URL=https://your-provider.example/v1
AI_MODEL=your-model-id
AI_API_KEY=your-api-key
AI_TIMEOUT_MS=45000
AI_MAX_OUTPUT_TOKENS=16000
```

Провайдер должен поддерживать `POST {AI_BASE_URL}/chat/completions`, массив `messages`, `max_tokens` (для дерева по умолчанию до 16 000 токенов) и ответ `choices[0].message.content` с JSON. Базовый URL включает `/v1`, если этого требует провайдер. Отдельный SDK не нужен. Модель должна уметь возвращать JSON без Markdown; дерево проверяется по схеме, включая отсутствие циклов и недоступных узлов. Некорректные ответы отклоняются, сохранённая задача не теряется. Не все API с похожим интерфейсом полностью совместимы — проверяйте выбранную модель.

В облачном режиме:

- На главной введите проблему. В задаче уточните результат, срок и ограничения, затем постройте дерево.
- В «Идеях» нажмите «Предложить идеи». Принятие рекомендации создаёт задачу; генерация её дерева выполняется после уточнений.
- Откройте наставника в задаче: он получает контекст выбранного пути, выполненных действий, результата и последних сообщений.

Для моделей с поддержкой принудительных function calls можно задать `AI_JSON_MODE=tool`: результат возвращается аргументами единственного инструмента `lifepilot_result` и проверяется той же Zod-схемой. Инструмент служит форматом ответа и не выполняет внешних действий. Без этого параметра используется JSON в текстовом ответе; допускается одна внешняя Markdown-обёртка JSON.

Ключ не отправляется в браузер. Сервер ограничивает AI-запросы шестью в минуту на аккаунт и задаёт таймаут. В модель передаётся контекст текущей задачи и целей пользователя, а для рекомендаций — профиль и названия задач. AI не меняет отметки выполнения и достижения. Дерево должно содержать 3–5 содержательных уровней выбора (цель — 4), конкретные преимущества и риски каждого варианта и 4–6 действий в каждом конечном плане. Слишком короткие ответы отклоняются, а не сохраняются как готовый план.

## Ошибки и диагностика

Успешные ответы API сохраняют прежнюю форму. Ошибка содержит `error` (безопасный текст), `code`, `requestId` и `retryable`; тот же идентификатор есть в заголовке `X-Request-Id`. Server Actions сохраняют `data`/`error` и добавляют эти диагностические поля. Некорректный запрос получает 400, отсутствие сессии — 401, запрещённый источник — 403, отсутствующая задача/документ — 404, конфликт/устаревший контекст — 409, размер — 413, лимит — 429. Внутренняя ошибка — 500, некорректный ответ AI/внешний сбой — 502, недоступность/настройка — 503, таймаут AI — 504. Неожиданные исключения не раскрываются клиенту.

Тела запросов ограничиваются по фактически прочитанным байтам, включая поток без `Content-Length`: AI — 16 000 байт, локальные JSON-команды — 2 МиБ, multipart — 5 МиБ + 20 000 байт; сам файл — 5 МиБ. Ответ AI ограничен 200 000 байт, CalDAV — 10 МиБ (отдельное событие — 2 МиБ). Превышение останавливает чтение. `AI_BASE_URL` должен быть HTTP(S) URL без встроенных учётных данных, query и fragment; `AI_TIMEOUT_MS` — 1000–60000, `AI_MAX_OUTPUT_TOKENS` — целое 4000–24000. Усечение `finish_reason=length` отклоняется даже при синтаксически корректном JSON.

Лимит AI резервируется после проверки задачи, повторно проверяемой внутри транзакции. Пара «вопрос + ответ наставника» сохраняется атомарно. Изменение задачи, цели профиля или диалога до сохранения результата даёт `STALE_CONTEXT`; ответ не записывается, выполненный запрос учитывается в лимите. Неудачный запрос к провайдеру также расходует резерв — это ограничивает повторные обращения при сбое.

При проблеме найдите в stdout JSON-запись с `requestId` или `jobId`. Она содержит только операцию, код, длительность и (у задания) попытку. Пароли, ключи, содержимое документов, диалоги и ответы провайдеров в эти записи не попадают. Пример:

```json
{
  "operation": "ai.generate",
  "code": "AI_TIMEOUT",
  "durationMs": 45001,
  "requestId": "example-id"
}
```

Для локального агента смотрите фазу в карточке задачи. При временной ошибке выполняется не более пяти попыток; потеря lease, смена подключения и версии плана прекращают устаревшую работу. Смена подключения или расписания заново ставит незавершённые планы в очередь. Готовые события сохраняются; для перепланирования готовой задачи используйте её явное действие повтора.

## Поведение приложения

- **Главная:** календарь и поле вопроса. Нажатие даты только раскрывает задачи выбранного дня. Категории имеют одинаковые цвета во всех экранах.
- **Мои задачи:** задачи из поля «Что сейчас занимает твои мысли?», принятых идей и готовых сценариев; поиск, категории и сортировка. Отдельной формы ручного добавления нет.
- **Идеи:** AI-рекомендации и библиотека шести готовых сценариев, доступных без модели. Каждое новое прохождение — отдельная задача.
- **Дерево:** каждый из шести готовых сценариев содержит четыре последовательных решения и 31 узел. Следующий вопрос зависит от выбранного варианта; конечные действия учитывают весь путь. Для стирки: тип вещей → допустимая температура → загрязнение → способ сушки. Для экзамена: способ подготовки → срок → формат → проверка знаний. У вариантов есть конкретные плюсы и риски. Предыдущие уровни остаются видимыми; незавершённый путь можно изменить.
- **Выполнение:** только галочка «Сделано / не сделано», без процентов, шкал, баллов и уровней навыка. Её можно поставить или снять в списке и внутри задачи, даже если AI-дерево ещё не создано. Отметка всей задачи отмечает действия выбранного чек-листа; выполнение всех его действий тоже отмечает задачу. Снятие отметки задачи открывает её заново и снимает отметки текущего чек-листа. Отзыв о предыдущем результате сохраняется в истории.
- **Достижения:** пять круглых значков в профиле: выбрать путь, выполнить первую задачу, выполнить две задачи, выполнить задачи в трёх категориях, выполнить пять задач. Полученные значки не исчезают при повторном открытии задачи и не дублируются.
- **Совместимость:** старые сохранённые отметки и результаты читаются без сброса. Нетронутые готовые планы обновляются автоматически. Для уже начатого старого сценария кнопка «Открыть подробный вариант» создаёт новое прохождение, сохраняя исходное дерево и результат.
- **Напоминания:** только внутри открытого приложения, на основе собственных дат пользователя. Инициативные вопросы изначально выключены. Вопросы учитывают согласие, настройки, частоту и часовой пояс. Нет push, фоновой доставки или внешнего календаря. Обработка происходит при открытии облачного аккаунта или действии пользователя. Для демонстрации включите инициативные вопросы и нажмите «Проверить демо-событие» в настройках.
- **Приватность:** очистка истории удаляет диалоги, текст обратной связи и текущие уведомления; задачи и отметки выполнения сохраняются. Удаление аккаунта удаляет связанные данные. В демо соответствующая кнопка очищает только localStorage.

## Устройство

- `src/lib/domain/` — схемы и типы (`schemas.ts`), обход дерева (`tree.ts`), выполнение/совместимость задач (`tasks.ts`), команды (`commands.ts`) и проверка актуальности AI-контекста (`context.ts`). `src/lib/domain.ts` сохраняет прежние экспорты.
- `src/lib/config.ts` — определение режимов и проверка AI-конфигурации в месте использования; не зависит от Supabase.
- `src/lib/errors.ts`, `src/lib/http.ts` — публичные ошибки, потоковые лимиты, JSON, Origin/Host и диагностика.
- `src/lib/scenarios.ts` — библиотека сценариев с конкретными действиями и подсказками.
- `src/lib/store.ts` — версия документа и optimistic concurrency: условная запись JSONB по `user_id` и `revision`, повтор после конфликта. Отметки действий, статус задачи и достижения сохраняются одной операцией PostgreSQL.
- `src/lib/server/` — операции аккаунта, AI и локального профиля. Server Actions и HTTP-обработчики проверяют доступ/входные данные и формируют ответ.
- `src/hooks/use-life-pilot.ts` — состояние и пользовательские операции; `use-local-polling.ts` — последовательный polling; `src/lib/client-request.ts` — транспорт и отмена устаревших запросов.
- `src/components/screens/` — самостоятельные экраны; `thought-form.tsx` — ввод вопроса и вложения. `LifePilot` собирает навигацию и экраны.
- `src/components/` — экраны и общие элементы; `src/app/globals.css` — визуальная система и адаптивная вёрстка.

Сущности пользователя, задач, дерева, обратной связи, диалогов, рекомендаций и достижений сохраняются в одном типизированном документе `user_state.state` версии 1. Бинарное выполнение и история отзывов совместимы со старыми документами. Поля старых баллов сохраняются для совместимости, но не изменяются и не отображаются. Для MVP это позволяет атомарно обновлять несколько связанных сущностей. Изменение формата документа требует явной миграции версии; неизвестная версия не загружается. Лимит — 500 задач на аккаунт; в диалоге хранится до 100 сообщений, в AI-контекст передаются последние 16.

## Проверки

```bash
npm run typecheck
npm run lint
npm run format:check
npm test
npx playwright install chromium
npm run test:e2e
npm run test:db
npm run build
npm start
```

Перед браузерными тестами автоматически выполняется production-сборка. Playwright поднимает отдельный production-сервер на порту **3210**, не переиспользует чужие процессы и проверяет Chromium на desktop и mobile viewport. Скриншоты и trace сохраняются в ignored `test-results/`. `npm run test:db` требует Docker и образ `postgres:17-alpine` (при отсутствии: `docker pull postgres:17-alpine`); запускает временную изолированную БД без публикации портов и постоянных томов и удаляет контейнер после проверки.

Дополнительные проверки локального режима:

```bash
# Radicale устанавливается отдельно, например во временное Python-окружение:
python3 -m venv /tmp/lifepilot-radicale
/tmp/lifepilot-radicale/bin/pip install radicale==3.8.3
RADICALE_BIN=/tmp/lifepilot-radicale/bin/radicale npm run test:caldav
RADICALE_BIN=/tmp/lifepilot-radicale/bin/radicale npm run test:local
# Использует настроенную AI-модель; один готовый сценарий и тестовый календарь:
RADICALE_BIN=/tmp/lifepilot-radicale/bin/radicale npm run smoke:local
```

Скрипты создают временные профиль и Radicale, выделяют свободные loopback-порты и удаляют тестовые данные после завершения. `test:local` использует детерминированный тестовый AI и Chromium; `smoke:local` делает ограниченный запрос к настроенной модели, создаёт события только в тестовом Radicale и проверяет их удаление после выполнения. Radicale не входит в runtime приложения. Совместимость подтверждается отдельно с каждым сервером: наличие CalDAV не доказывает совместимость всех провайдеров и их вариантов авторизации. Тесты iCalendar покрывают занятость, повторения и исключения, многодневные события, IANA-пояса и DST; при неизвестном часовом поясе или слишком сложном повторении планирование прекращается с ошибкой.

Unit-тесты проверяют бинарное выполнение, повторное открытие задач, сохранение старых планов, глубину деревьев и смену веток, согласие, ограничения AI, валидацию и ошибки транспорта. Проверка PostgreSQL подтверждает миграцию, RLS, запрет клиентских записей, CAS и каскад удаления. Она использует минимальные тестовые роли Auth и не подменяет проверку настоящего Supabase Auth. Тесты AI используют mock транспорта, а не живую модель. Тесты самих обработчиков и Server Actions проверяют доступ, статусы, потоковый размер, безопасные ошибки и лимиты; тесты записи — атомарность диалога, конкурентные CAS и отклонение устаревших результатов.

`npm run test:e2e` также проверяет ширины 360/390/768/1024/1440 px с размером текста 100/125/200%, длинные URL, кириллицу/латиницу и настоящий zoom вкладки Chromium 125/200%. Для zoom создаётся временный профиль и тестовое расширение, удаляемые после проверки. Скриншоты: `test-results/cloud/`, локальный сценарий: `test-results/local/`; HTML-отчёты: `playwright-report/cloud/` и `playwright-report/local/`. Локальные тесты в обычном E2E прогоне пропускаются намеренно и выполняются через `test:local` с изолированным профилем. Итог конкретного прогона описан в [отчёте рефакторинга](docs/refactor-verification.md).

Перед публичной приёмкой отдельно проверьте реальную регистрацию и письма восстановления, два разных аккаунта, сохранение между устройствами, генерацию деревьев для разных вопросов и ответы наставника выбранной модели.

## Публикация на Vercel

Импортируйте репозиторий как Next.js-проект, задайте Node.js 22 и перечисленные переменные окружения в настройках Vercel. Примените миграцию к рабочему Supabase, обновите Site URL, Redirect URL и почтовые шаблоны на публичный домен. Build command — `npm run build`, зависимости устанавливаются из `package-lock.json`. Vercel управляет запуском самостоятельно; локальный порт 3010 не является настройкой хостинга.

После деплоя пройдите основной сценарий по HTTPS-ссылке без календарных интеграций. Проверяйте Preview и Production раздельно: переменные и разрешённые редиректы могут различаться. Внешние аккаунты, ключи и публичный деплой не создаются автоматически этим репозиторием.

Содержание готовых планов — помощь в подготовке. В стирке температура, программа и сушка всегда сверяются с [символами ухода GINETEX](https://www.ginetex.ch/en/pflegekennzeichnung/pflegesymbole/); температура на ярлыке — верхний предел. Размер финансового резерва зависит от обстоятельств, что соответствует [руководству CFPB по аварийному резерву](https://www.consumerfinance.gov/an-essential-guide-to-building-an-emergency-fund/). Приложение не выбирает финансовые продукты и не выполняет платежи.
